# I4.25 — Persist stale DLQ digest suppression to Postgres

**Increment:** I4.25  
**Server version:** `0.65.0-pg27-i3.27-i4.25`

## Summary

Dual-write I4.24 snooze/ack when `EOS_DATABASE_URL` / `dbPool` is set, and hydrate on API startup. Dispatching the digest deletes the row so a later stale cycle can reappear.

## Migration

`060_i425_dlq_sla_digest_stale_suppression.sql` — table `notif_dlq_sla_digest_stale_suppression` (PK `tenant_id`).

## Behaviour

- `upsertStaleSuppression` fire-and-forget `upsertNotifDlqSlaDigestStaleSuppression`
- `stampLastRun` deletes the tenant row in memory and Postgres
- Startup hydrate via `hydrateNotifDlqSlaDigestStaleSuppressions`
