# I4.31 — Persist named DLQ stale-audit export presets

**Increment:** I4.31  
**Server version:** `0.98.0-i4.31`

## Summary

Dual-write named tenant DLQ stale-audit export presets when `EOS_DATABASE_URL` / `dbPool` is set, and hydrate on API startup. Invalid names / windows do not persist. Status GET still echoes `presets` without persisting.

## Migration

`075_i431_dlq_sla_digest_stale_audit_export_preset.sql` — table `notif_dlq_sla_digest_stale_audit_export_preset` (PK `id`, unique `(tenant_id, lower(name))`).

## Behaviour

- Successful `POST …/dlq-sla-digest-stale/export/presets` awaits persist
- Empty / invalid name or filter does not persist
- Hydrate log: `i431_dlq_sla_digest_stale_audit_export_preset_hydrate`
- Status GET echoes sanitized `presets` (no persist)
