## Problem statement

I4.30 added named tenant DLQ stale-audit export presets. I4.31 persists them. Operators can create or upsert by **name**, including filter fields.

They cannot rename or delete a preset by id without overwriting filters via upsert. I4.31 explicitly deferred “Rename / delete presets”.

I3.35 already closed the same gap for allowlist presets. I4.32 applies that **behavioural** pattern to the I4.31 DLQ store. It does not invent I3.36, I20.23, or PG.30.

## Objective

When implementation is later authorized:

- Rename a tenant DLQ stale-audit export preset by id
- Delete a tenant DLQ stale-audit export preset by id
- Keep I4.30/I4.31 upsert-by-name, list, apply-on-export, and hydrate
- Stay inside the existing ADR-0017 Dev/Test dual-write boundary

## Validation rules

Reuse `normalizeNotifDlqSlaDigestStaleAuditExportPresetName`:

- Trim and collapse internal whitespace
- Empty / whitespace-only → `invalid_name`
- Length > 80 → `invalid_name`

## Authorization rules

| Operation | Permission | `authorize` action |
| --- | --- | --- |
| Rename | `notification:dispatch:email` | `rename:dlq_sla_digest_stale_audit_export_preset` |
| Delete | `notification:dispatch:email` | `delete:dlq_sla_digest_stale_audit_export_preset` |
| List / status / export | `notification:read:email_outbox` | unchanged (I4.31) |

Deny → `{ error: "forbidden", reason }`.  
**403 fixture:** Bob (no dispatch). Do not use Alice (Alice has dispatch).

Not `ai:write:draft`.

## Tenant isolation

- Lookup is `tenantId === principal.tenantId` **and** `id`
- Other-tenant id → `404` `preset_not_found`
- Name clash only inside the caller tenant
- Unique `(tenant_id, lower(name))` already enforces this in PG

## Rename semantics

1. Authorize write.
2. Normalize `name`. Fail `invalid_name` with no store write.
3. Find by id in the caller tenant. Missing → `preset_not_found`.
4. If another tenant row has the same normalized name → `name_taken`.
5. Same-id case-only rename is allowed.
6. Keep `id`, `tenantId`, `createdAt`, `createdByPrincipalId`, `action`, `since`, `until`.
7. Set `name` and `updatedAt`; replace in-memory row.
8. Await I4.31 upsert persist when `dbPool` is set.
9. Return sanitized preset + tenant list.

Rename does not upsert filter fields and does not record a recommend run.

## Delete semantics

1. Authorize write.
2. Find by id in the caller tenant. Missing → `preset_not_found`.
3. Hard-delete the in-memory row.
4. Await persist-delete by `id` when `dbPool` is set.
5. Return remaining sanitized tenant presets.

After delete: list/status omit the row; export with that `preset` / `presetId` → `404` `preset_not_found`.

## Idempotency

- No `Idempotency-Key` (I4.31 upsert and I3.35 rename/delete have none).
- Repeat delete of a missing id → `404` `preset_not_found` (not 200).
- Repeat rename to the same normalized name on the same id → 200 (self, not a clash).

## Conflict / optimistic concurrency

I4.31 presets have no `If-Match` / version token. I4.32 does **not** add one.

| Condition | `error` | `reason` | HTTP |
| --- | --- | --- | --- |
| Missing/invalid session | `unauthenticated` | — | 401 |
| Missing write permission | `forbidden` | authorize reason | 403 |
| Empty / over-80 name | `invalid_request` | `invalid_name` | 400 |
| Unknown or other-tenant id | `not_found` | `preset_not_found` | 404 |
| Name owned by another preset in the tenant | `conflict` | `name_taken` | 409 |

Invalid rename/delete must not persist. Reuse existing notification `sendError` `conflict` → 409 (shipped with I3.35).

## Persistence (Dev/Test boundary)

No new migration. Reuse `075_i431_dlq_sla_digest_stale_audit_export_preset.sql`.

| Operation | PG |
| --- | --- |
| Rename | Existing `persistNotifDlqSlaDigestStaleAuditExportPreset` (`INSERT … ON CONFLICT (id) DO UPDATE`) |
| Delete | New `deleteNotifDlqSlaDigestStaleAuditExportPreset(pool, id)` + `persistDeleteNotifDlqSlaDigestStaleAuditExportPreset` — `DELETE FROM notif_dlq_sla_digest_stale_audit_export_preset WHERE id = $1` |

Hydrate stays I4.31 (`merge` by `id`). Failed dual-write is try/catch after the in-memory write (I4.31 / I3.35). In-memory remains Dev/Test read SoR (ADR-0017). **Not** production SoR. Does not create PG.30. Does not reopen ADR-0017.

| `store.dbPool` | Rename | Delete |
| --- | --- | --- |
| unset | Memory only | Memory only |
| set | Await upsert | Await delete-by-id |
| query throws | Return in-memory result; swallow persist error | Same |

Status GET still echoes `presets` and does **not** persist.
