# I20.13 — Persist recommend stale snooze / ack

**Increment:** I20.13  
**Server version:** `0.80.0-i20.13`  
**Autonomy:** Level 1 (Recommend) snapshot only.

## Summary

Dual-write I20.12 snooze/ack when `EOS_DATABASE_URL` / `dbPool` is set, and hydrate on API startup. Recording a new recommend last-run deletes the row so a later stale cycle can reappear.

## Migration

`066_i2013_ai_recommend_stale_suppression.sql` — table `ai_recommend_stale_suppression` (PK `tenant_id, principal_id`).

## Behaviour

- Snooze/ack await `persistAiRecommendStaleSuppression`
- Recommend restamp deletes the tenant+principal row in memory and Postgres
- Startup hydrate via `hydrateAiRecommendStaleSuppressions`
