# I4.29 — Persist last-used DLQ stale-audit filter

**Increment:** I4.29  
**Server version:** `0.94.0-i4.29`

## Summary

Remember the last successful DLQ SLA digest stale-audit export filter (`action` / `since` / `until`) per tenant + principal. Dual-write when `EOS_DATABASE_URL` / `dbPool` is set, and hydrate on API startup. Status GET echoes sanitized `lastFilter` without persisting.

## Migration

`073_i429_dlq_sla_digest_stale_audit_export_last_filter.sql` — table `notif_dlq_sla_digest_stale_audit_export_last_filter` (PK `tenant_id, principal_id`).

## Behaviour

- Successful stale export awaits persist of the last-used filter
- Invalid action / window does not persist
- Status GET echoes sanitized `lastFilter` (no `tenantId` / `principalId`)
- Commercial Events prefills action / since / until from `lastFilter` once
