# I3.32 — Persist last-used allowlist stale-audit filter

**Increment:** I3.32  
**Server version:** `0.93.0-i3.32`

## Summary

Remember the last successful allowlist stale-audit export filter (`action` / `since` / `until`) per tenant + principal. Dual-write when `EOS_DATABASE_URL` / `dbPool` is set, and hydrate on API startup. Status GET echoes sanitized `lastFilter` without persisting.

## Migration

`072_i332_allowlist_dual_digest_stale_audit_export_last_filter.sql` — table `notif_allowlist_dual_digest_stale_audit_export_last_filter` (PK `tenant_id, principal_id`).

## Behaviour

- Successful stale export awaits persist of the last-used filter
- Invalid action / window does not persist
- Status GET echoes sanitized `lastFilter` (no `tenantId` / `principalId`)
- Commercial Notifications prefills action / since / until from `lastFilter` once
