# I4.18 — External cron hook for DLQ SLA digest

Wire a scheduler (GitHub Actions, CloudWatch Events, k8s CronJob, etc.) to call the existing digest endpoint on a cadence. EOS does not run an in-process cron; ops owns the schedule.

## Endpoint

`POST /v1/notifications/email/dispatch-dlq-sla-digest`

Requires Bearer token for a principal with `notification:dispatch:email` and `events:read:dlq`.

## Example (daily 07:00 UTC)

```bash
curl -sS -X POST "$EOS_API_BASE/v1/notifications/email/dispatch-dlq-sla-digest" \
  -H "Authorization: Bearer $EOS_OPS_TOKEN" \
  -H "Content-Type: application/json"
```

## Behaviour (unchanged from I4.16/I4.17)

- Fans out to caller + store/env ops aliases (`EOS_DLQ_SLA_DIGEST_RECIPIENTS`)
- Outbox key `dlq-sla-digest:{yyyy-mm-dd}:{email}` — **idempotent per recipient per UTC day**
- Empty breaches → skipped `none_breached`
- Same-day redispatch → skipped `already_dispatched` (or equivalent adapter skip)
- Banner: `I4.18`

## Ops checklist

1. Create a long-lived ops principal / token with digest + DLQ read permissions (rotate regularly).
2. Schedule one daily POST; retries within the same UTC day are safe.
3. Confirm recipients via `GET /v1/notifications/email/dlq-sla-digest-recipients`.
4. Alert on non-2xx from the hook (auth failure, upstream down).
