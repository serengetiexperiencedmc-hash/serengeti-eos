# I20.2 — AI draft artefacts (human accept)

**Increment:** I20.2  
**Server version:** `0.69.0-i20.2`  
**Autonomy:** Level 2 (Draft). Unpublished until a human accepts.

## Summary

Turn an active I20.1 recommendation into a **pending CRM-task draft**. Nothing is written to CRM until a human accepts. Discard drops the draft. The assistant still cannot merge, email, assign owners, or approve.

## Port

`packages/kernel/src/ai-draft.ts` — artefact type `crm_task` only. Unknown keys (including `crm.merge.execute`) are rejected. Autonomy is fixed at 2.

## API

| Method | Path | Permission |
| --- | --- | --- |
| `POST` | `/v1/ai/drafts` `{ recommendationKey }` | `ai:write:draft` |
| `GET` | `/v1/ai/drafts?status=pending` | `ai:read:recommend` |
| `POST` | `/v1/ai/drafts/:id/accept` | `ai:write:draft` + human `crm:write:task` |
| `POST` | `/v1/ai/drafts/:id/discard` | `ai:write:draft` |

Create only succeeds when that recommendation is **currently active** for the caller. A pending draft for the same tenant + user + key is reused (`replay: true`).

Accept is the only write path. It calls the existing `createTask()` helper with the human principal. AiAgent principals are denied on `accept:*` (`ai_cannot_approve`).

Drafts are in-memory (`store.aiDrafts`) this increment. No Postgres migration.

## UI

Commercial Dashboard: **Draft** next to **Open**; pending drafts show **Accept** / **Discard**. Programme builder no longer shows fake itinerary write buttons.

## Not included

- LLM providers (ADR-0008: same `dev-rules` port)
- Merge, email, owner-assign, or other artefact types
- Autonomous apply (L3+)
- Persisted draft store
