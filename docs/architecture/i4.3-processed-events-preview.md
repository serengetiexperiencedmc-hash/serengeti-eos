# I4.3 — Processed Events PG Persistence + Consumer Replay

**Increment:** I4.3  
**Server version:** `0.36.0-i4.3-pg4`

## Summary

Extends I4.2 idempotent consumers with PostgreSQL durability for `processed_events` and a Dev/Test consumer replay API distinct from DLQ/outbox replay.

## Persistence

| Layer | Change |
| --- | --- |
| Migration | `039_pg_i43_processed_events.sql` — tenant/consumer index |
| Repository | `insertProcessedEvent`, `loadProcessedEvents`, `countProcessedEvents` |
| Facade | `persistence/processed-events.ts` |
| Runtime | `consumeEventIdempotent` dual-writes; `hydrateProcessedEvents` on startup |
| Startup | `main.ts` hydrates before `initEventConsumers` |

## Consumer replay API

| Route | Permission | Purpose |
| --- | --- | --- |
| `GET /v1/events/consumers/processed` | `events:read:operations` | List idempotency keys for tenant |
| `POST /v1/events/consumers/replay` | `events:consume:outbox` | Re-deliver event(s) to a consumer; optional `force: true` bypasses idempotency |

Replay resolves envelopes from published outbox records. Audit action: `events:consumer_replay`.
