# I3.34 — Persist named allowlist stale-audit export presets

**Increment:** I3.34  
**Server version:** `0.96.0-i3.34`

## Summary

Dual-write named tenant allowlist stale-audit export presets when `EOS_DATABASE_URL` / `dbPool` is set, and hydrate on API startup. Invalid names / windows do not persist. Status GET still echoes `presets` without persisting.

## Migration

`074_i334_allowlist_dual_digest_stale_audit_export_preset.sql` — table `notif_allowlist_dual_digest_stale_audit_export_preset` (PK `id`, unique `(tenant_id, lower(name))`).

## Behaviour

- Successful `POST …/allowlist-dual-digest-stale/export/presets` awaits persist
- Empty / invalid name or filter does not persist
- Hydrate log: `i334_allowlist_dual_digest_stale_audit_export_preset_hydrate`
- Status GET echoes sanitized `presets` (no persist)
