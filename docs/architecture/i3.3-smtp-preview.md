# I3.3 SMTP Email Transport — Preview

Increment **I3.3** adds real SMTP sending for notification emails when a relay is configured.

## Kernel

- `packages/kernel/src/notification-smtp.ts` — `SmtpTransportConfig`, `parseSmtpConfigFromEnv()`, `isSmtpConfigured()`

## API

- `apps/api/src/notifications/smtp-transport.ts` — minimal SMTP client for Dev/Test relays (Mailhog, etc.)
- Adapter name **`smtp`** when `EOS_EMAIL_ADAPTER=smtp` and `EOS_SMTP_HOST` is set
- Falls back to **`smtp-stub`** if adapter is `smtp` but host is missing

## Environment

| Variable | Description |
| --- | --- |
| `EOS_EMAIL_ADAPTER` | `dev-outbox` (default), `smtp-stub`, or `smtp` |
| `EOS_SMTP_HOST` | SMTP relay hostname |
| `EOS_SMTP_PORT` | Default `587` (use `1025` for Mailhog) |
| `EOS_SMTP_FROM` | From address |
| `EOS_SMTP_USER` / `EOS_SMTP_PASS` | Optional auth |
| `EOS_SMTP_SECURE` | `true` for TLS on connect (port 465) |

## Dev setup (Mailhog)

```yaml
# docker run -p 1025:1025 -p 8025:8025 mailhog/mailhog
EOS_EMAIL_ADAPTER=smtp
EOS_SMTP_HOST=127.0.0.1
EOS_SMTP_PORT=1025
EOS_SMTP_FROM=noreply@sedmc.local
```
