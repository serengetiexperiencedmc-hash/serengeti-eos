## 5. Operating-process principles

The design favours:

- one accountable opportunity owner;
- clear qualification **before** significant costing effort;
- structured clarification;
- `SOURCE ≠ CHANNEL`;
- `MARKET ≠ ACCOUNT TYPE ≠ DESTINATION`;
- explicit next action;
- explicit loss classification;
- proposal version discipline;
- approval evidence for **exceptional** commercial decisions;
- supplier-rate provenance;
- minimum necessary evidence capture;
- auditability **without** unnecessary document duplication;
- human commercial judgment where rules do **not** specify a numerical threshold.

The design avoids:

- artificial scoring;
- unauthorized numerical thresholds;
- hidden qualification rules;
- inferred margin floors;
- automatic qualification;
- automatic loss classification;
- automatic commercial approvals;
- inferring SOURCE from CHANNEL;
- inferring market from destination, email domain, account name, or buyer type;
- inventing a loss reason from insufficient evidence;
- copying unnecessary originals into EOS.

## 6. End-to-end commercial process

Recommended operating sequence:

**RFP / opportunity intake → initial clarification → qualification → programme development → costing / supplier evidence → commercial approval (if required) → proposal issuance → follow-up → negotiation → won / lost / deferred closure → post-close evidence**

Account / SOURCE / market classification, ownership, and evidence discipline apply **across** stages. They are not a single late-stage afterthought.

For every stage the same eight elements apply: **purpose · responsible role · minimum information · evidence expected · decision/action · handoff condition · exception/escalation · next-action expectation**.

Staff may record these elements in the tools they already use (email, Office notes, trackers, WhatsApp, telephone notes), provided the **facts are recoverable** when needed. Originals need not be copied into EOS.

### Stage 1 — RFP / opportunity intake

| Element | Operating design |
| --- | --- |
| Purpose | Register a genuine inbound or originated commercial enquiry as an opportunity with an owner. |
| Responsible role | Assigned Sales & BD opportunity owner (Commercial Director may allocate). |
| Minimum information | Received date/time as known; CHANNEL of intake; tentative account identity; subject/requirement in the enquirer’s words; assigned owner. |
| Evidence expected | Pointer to the original intake (mailbox thread, web form, call note, WhatsApp, in-person note). Original may remain in its operational system. |
| Decision / action | Accept as an opportunity to review, or immediately redirect if it is clearly not SEDMC commercial work (e.g. unrelated FIT reservation). Do **not** treat intake as qualification. |
| Handoff | Owner named; CHANNEL labelled; SOURCE labelled **if known**, else marked **unlabelled / to be established** — do **not** infer SOURCE from CHANNEL. |
| Exception / escalation | Unclear ownership, sensitive/strategic sender, or conflict of coverage → Commercial Director. |
| Next-action expectation | Explicit next action: review and, if needed, clarify. Owner and due point named. |

### Stage 2 — Initial clarification

| Element | Operating design |
| --- | --- |
| Purpose | Obtain enough verified information to apply OR-01 without committing significant costing/proposal effort. |
| Responsible role | Opportunity owner. |
| Minimum information | Missing OR-01-B items; questions asked; answers received; dates of request and answer where known. |
| Evidence expected | Clarification correspondence or call/WhatsApp note. Status: requested / answered / not applicable. |
| Decision / action | Continue toward qualification, request further clarification, or stop if the enquiry is not a genuine commercial opportunity. |
| Handoff | OR-01-B items are sufficiently established **or** it is clear they cannot be established. |
| Exception / escalation | Client unresponsive, contradictory scope, or strategic account → Commercial Director. |
| Next-action expectation | Qualify, decline/park, or ask a defined further question. Silent holding is not a next action. |

### Stage 3 — Qualification

See §7. Summary: apply OR-01 after clarification and **before** significant proposal/costing. No numerical budget gate. No automatic qualification.

### Stage 4 — Opportunity ownership (standing discipline)

| Element | Operating design |
| --- | --- |
| Purpose | Keep one named human accountable from intake through close. |
| Responsible role | Assigned Sales & BD opportunity owner. |
| Minimum information | Current owner; if transferred: previous owner, new owner, reason, next action. |
| Evidence expected | Named owner on the working record (Office/email/EOS note — wherever the live file is). |
| Decision / action | Owner remains accountable for follow-up, proposal version, loss/win recording. |
| Handoff | Transfer only under OR-04 conditions (§11). |
| Exception / escalation | Overdue, strategic, or sensitive → Commercial Director (§15). |
| Next-action expectation | Always a current next action while the opportunity is open. |

### Stage 5 — Programme development

| Element | Operating design |
| --- | --- |
| Purpose | Shape a client-facing programme that fits destination/service capability after qualification. |
| Responsible role | Opportunity owner; operations/programme support as allocated. |
| Minimum information | Destination(s); approximate dates or window; group size/profile; scope sufficient to cost. Destination is **not** market. |
| Evidence expected | Working programme note/version identity (Office/email). Do not require EOS duplication. |
| Decision / action | Proceed to costing when scope is sufficient; return to clarification if it is not. |
| Handoff | Programme identity/version that costing will use. |
| Exception / escalation | Capacity, destination-fit, or high-risk complexity → Commercial Director / operations. |
| Next-action expectation | Cost, seek supplier evidence, or re-clarify a named gap. |

### Stage 6 — Costing / supplier evidence

| Element | Operating design |
| --- | --- |
| Purpose | Build a commercially responsible cost basis from identified supplier-rate provenance (§13). |
| Responsible role | Opportunity owner for the commercial file; supplier-management function for rate maintenance; Sales flags discrepancies. |
| Minimum information | Rate source class; rate type; original currency; validity/season; received/verified dates; item/service identity; version identity where a sheet exists. |
| Evidence expected | Pointer to the written source (contract, rate sheet, quotation). Original may remain outside EOS. |
| Decision / action | Cost on current verified rates, or reconfirm expired/unverified rates **before** commitment. |
| Handoff | Cost basis ready for ordinary send **or** identified as requiring exceptional approval. |
| Exception / escalation | Missing provenance, expired rates, public-only rates proposed for sale without approval → do not send; escalate. |
| Next-action expectation | Approve if required, or prepare the proposal version. |

No FX provider, automated FX, currency conversion implementation, supplier connector, or procurement integration is designed or authorized here. Original currency is **retained**.

### Stage 7 — Commercial approval (if required)

See §12. Ordinary proposals within approved **qualitative** parameters do not require unnecessary executive approval. Exceptional cases require approval **before send**. No new numerical thresholds.

### Stage 8 — Proposal issuance

| Element | Operating design |
| --- | --- |
| Purpose | Send the **final approved commercial version**. |
| Responsible role | Opportunity owner (OR-05). |
| Minimum information | Proposal identity/version; sent date as known; CHANNEL of send if different from intake CHANNEL (intake CHANNEL is **not** overwritten); confirmation that required approval is complete or not required. |
| Evidence expected | Pointer to the sent artefact in its operational location. Do not require the file to be copied into EOS. |
| Decision / action | Send only the approved version. Prior drafts are not the sent version. |
| Handoff | Proposal sent; follow-up next action set. |
| Exception / escalation | Last-minute commercial change → re-check approval before send. |
| Next-action expectation | Named follow-up (who, what, by when). |

### Stage 9 — Follow-up

See §11. Owner remains accountable through negotiation and close.

### Stage 10 — Negotiation

| Element | Operating design |
| --- | --- |
| Purpose | Handle commercial iteration without losing version identity or required approvals. |
| Responsible role | Opportunity owner. |
| Minimum information | What changed; whether the change is exceptional (OR-06); current proposed version. |
| Evidence expected | Correspondence and revised version identity. |
| Decision / action | If terms become exceptional, obtain approval **before** the new version is sent. |
| Handoff | Revised approved version, or close path (won/lost/deferred). |
| Exception / escalation | Strategic/high-risk movement in terms → Commercial Director. |
| Next-action expectation | Send revised version, wait for client, or close. |

### Stage 11 — Won / lost / deferred closure

| Element | Operating design |
| --- | --- |
| Purpose | Close the opportunity with an explicit outcome. |
| Responsible role | Opportunity owner records; Commercial Director may review/reclassify. |
| Minimum information | Outcome: won / closed-lost / deferred. If lost: exactly one primary LR-01–LR-12; optional contributing reasons; LR-12 explanation if used. If won: booking/contract pointer where it exists. If deferred: reason and next review point (LR-06 may apply if closed-lost-as-deferred is the chosen state; do not invent). |
| Evidence expected | Client communication or internal note sufficient to support the outcome. Do **not** invent a loss reason. |
| Decision / action | Formal close. Loss reasons become final at closed-lost. |
| Handoff | Closed record; post-close evidence if won. |
| Exception / escalation | Sensitive loss, disputed classification → Commercial Director. |
| Next-action expectation | None if fully closed; or a dated review if deferred and still open. |

### Stage 12 — Post-close evidence

| Element | Operating design |
| --- | --- |
| Purpose | Keep win/loss evidence recoverable without ingesting entire files into EOS. |
| Responsible role | Opportunity owner; operations for booking files where they exist. |
| Minimum information | Pointers: booking/contract if won; loss evidence if lost; SOURCE / CHANNEL / market / account type as labelled. |
| Evidence expected | Location of the operational file. Absence of a won-booking file means **booking evidence not established**, not that the booking process is defective. |
| Decision / action | Confirm the close file is findable. |
| Handoff | End of commercial cycle for this opportunity. |
| Exception / escalation | Missing contract after a claimed win → Commercial Director / operations. |
| Next-action expectation | None, unless a booking/contract gap must be resolved. |

## 7. Qualification process

OR-01 remains the definition. H-74 does **not** alter it.

### 7.1 Definition (OR-01-A)

A qualified RFP is a genuine commercial opportunity that:

- fits SEDMC’s target customer and destination/service capabilities;
- has a sufficiently defined programme requirement to pursue;
- has a credible buying process and decision timeframe;
- contains enough verified information for SEDMC to invest proposal and costing resources.

Budget information is **desirable** but **not** an absolute qualification requirement where the opportunity is otherwise credible and commercially viable.

### 7.2 Mandatory conditions (OR-01-B)

An RFP is qualified when the following are **sufficiently established** (perfect information is **not** required):

1. Buyer / account fit.
2. Genuine requirement.
3. Destination / service fit.
4. Approximate dates or credible decision window.
5. Sufficient programme scope.
6. Approximate group size or participant profile.
7. Buying process known or actively being established.
8. Commercial viability credible.
9. Defined next action.

The opportunity owner walks these nine conditions **explicitly**. They are not a score. They are not inferred from stage names such as `new_qualified`.

### 7.3 Timing and authority

- **When:** after initial RFP review / clarification and **before** significant proposal / costing effort (OR-01-D).
- **Who:** assigned Sales & BD opportunity owner (OR-01-C). Commercial Director retains oversight and may approve exceptions or reclassify strategic opportunities.
- **Changes:** qualification may change when new evidence emerges; material / strategic reclassification should be visible to the Commercial Director (OR-01-F).

### 7.4 Budget — explicit non-rule

```text
NO NUMERICAL BUDGET RULE IS AUTHORIZED
250K/20% = LEGACY / NOT APPROVED AS F2 QUALIFICATION RULE
```

Do **not** introduce a budget threshold.

Do **not** revive 250k / 20% as an active qualification rule.

Do **not** replace it with another numerical threshold.

Do **not** delete the legacy mixed residual (that is a software/governance residual, not an H-74 process rule).

If budget filtering is used in live conversation, treat it as **commercial judgment / process observation**, not as an EOS numerical gate, until a **separate** Owner decision says otherwise.

Budget, where available, may be recorded as **commercial evidence / context**. It does **not** become an unauthorized qualification gate.

### 7.5 Qualification operating checklist (human, not software)

Before significant costing, the owner should be able to answer:

| # | Condition | Established? | Evidence pointer / note |
| --- | --- | --- | --- |
| 1 | Buyer / account fit | yes / not yet / no | |
| 2 | Genuine requirement | yes / not yet / no | |
| 3 | Destination / service fit | yes / not yet / no | |
| 4 | Dates or decision window | yes / not yet / no | |
| 5 | Sufficient scope | yes / not yet / no | |
| 6 | Group size / profile | yes / not yet / no | |
| 7 | Buying process | yes / not yet / no | |
| 8 | Credible commercial viability | yes / not yet / no | |
| 9 | Defined next action | yes / not yet / no | |

**Not yet** → clarify. **No** on a mandatory condition, and not a Commercial Director exception → do not treat as qualified. **Do not auto-qualify.**

## 12. Proposal and approval discipline

Preserve OR-05 and OR-06.

### 12.1 Proposal send (OR-05)

The assigned Sales & BD owner may send a proposal **after** required approval / review conditions are satisfied and remains accountable for the **final approved commercial version**.

Operating practice:

- identify the version that will be sent;
- do not send a superseded draft as if it were the approved version;
- keep a pointer to the sent artefact in its operational location;
- set the follow-up next action at send.

### 12.2 When approval is required (OR-06)

Approval is required for exceptional cases, including:

- exceptional discounting;
- margin below approved floor;
- unusual payment / credit;
- non-standard cancellation / liability;
- significant contractual commitments;
- strategic / high-risk accounts;
- unusually large / complex programmes;
- deviations from supplier / commercial policy.

Ordinary proposals within approved parameters do **not** require unnecessary executive approval.

The “approved commercial floor” remains a **qualitative** reference. **No numerical value is authorized.**

### 12.3 No new numerical policy

```text
NO NEW NUMERICAL APPROVAL THRESHOLDS ARE AUTHORIZED BY H-74
NUMERICAL CPR = NOT AUTHORIZED
250K/20% REPLACEMENT = NOT AUTHORIZED
```

Do **not** create margin percentages, discount percentages, revenue thresholds, or approval-value thresholds.

Do **not** infer a floor from the legacy 250k / 20% mixed residual.

Do **not** auto-approve. Human commercial judgment applies where no numerical rule exists.

Path B qualitative exceptional categories (H-27 / H-38) remain the approved **non-numerical** approval model. H-74 does **not** implement them in software.
